# Functional coverage

Generated by `scripts/coverage_report.py --run` from the `coverage.json` files that the
unit and system tests write (`testbench/common/coverage.py`, D-034), merged over every
simulator and parameter set (25 simulations). Goal: at least one hit per bin.

**110 bins: 106 met, 4 documented gaps, 0 missed.**

## Documented gaps

- `gemm_engine` / row register -> postproc / stall (valid, not ready): unreachable, and asserted: with its output never stalled postproc never fills, so the row register never waits (a_pp_in_never_stalled).
- `gemm_engine` / postproc -> write port / stall (valid, not ready): unreachable, and asserted: the write ports accept a write every cycle, so the engine ties postproc's i_ready high (a_pp_out_never_stalled, gemm_engine_impl_sva.sv). Backpressure through postproc is covered by its unit test and formal proof.
- `accel_top` / network data: post-processing saturation / high: data property, not a design gap: no MNIST test image saturates high in any layer (model/reports/saturation.json, all 10,000 images). Covered by the postproc unit test (directed and random values) and its saturation mutant (m22).
- `accel_top` / network data: post-processing saturation / low: not in the quick subset: over all 10,000 test images conv2 saturates low only 4 times (images 3081, 5555, 8619, 9427; model/reports/saturation.json), and those images are bit-exact in the full run (testbench/reports/full_run.md). Covered in the postproc unit test.
