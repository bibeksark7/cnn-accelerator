# Functional coverage

Generated by `scripts/coverage_report.py --run` from the `coverage.json` files that the
unit and system tests write (`testbench/common/coverage.py`, D-034), merged over every
simulator and parameter set (25 simulations). Goal: at least one hit per bin.

**114 bins: 110 met, 4 documented gaps, 0 missed.**

## Documented gaps

- `gemm_engine` / row register -> postproc / stall (valid, not ready): unreachable: postproc's output is never stalled inside the engine (its i_ready is tied high), so its four stages never fill and its o_ready stays high.
- `gemm_engine` / postproc -> write port / stall (valid, not ready): unreachable: the buffer write port and the LOGIT registers accept a write every cycle, so the engine ties postproc's i_ready high. Backpressure through postproc is covered by the postproc unit test and its formal proof (testbench/formal/postproc.sby).
- `accel_top` / network data: post-processing saturation / high: data property, not a design gap: on the quick-subset images the network's requantized values stay inside int8, so real data never saturates in these runs. Saturation high and low is covered by the postproc unit test (directed and random values).
- `accel_top` / network data: post-processing saturation / low: data property, as for high saturation.
